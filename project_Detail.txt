The aim of this project is to build an AI-powered job search and resume-tailoring assistant that helps candidates find and evaluate relevant job opportunities based on their resume, skills, experience, preferred role, location, and other preferences. The MVP will initially use Adzuna as the primary job-data source and will later support additional sources such as Jooble and ATS platforms such as Greenhouse and Lever. The system will normalize and deduplicate job listings, rank them against the candidate profile using semantic similarity, use an LLM to analyze the best matches, identify matched and missing skills, and generate a tailored resume for a selected job. The system will maintain strict protection against fabricated information and will keep the final application submission under the user's control.

The main technologies will be Python, FastAPI, PostgreSQL, pgvector, Pydantic, Alembic, Docker, PyMuPDF, and an LLM such as OpenAI or Gemini. Adzuna will be the initial job API. PostgreSQL will store users, resumes, companies, jobs, job-analysis results, embeddings, and ingestion metadata. pgvector will be used for semantic matching without introducing a separate vector database. PyMuPDF will extract text from uploaded resumes, while structured LLM outputs will convert resume and job information into predefined Pydantic schemas. The LLM provider will be accessed through a small abstraction layer so OpenAI or Gemini can be switched later. Redis and Celery will be deferred until the application requires distributed caching or background processing. Database-level caching will be used initially to store Adzuna responses, job summaries, and embeddings and prevent unnecessary repeated LLM/API calls.

The development process will start with resume upload and parsing. The extracted resume will be converted into a structured candidate profile containing skills, experience, education, projects, achievements, and other relevant information. Next, the system will integrate Adzuna and retrieve jobs based on the user's role and location preferences. Each job will be normalized into a common schema containing fields such as source, source job ID, company, title, location, description, salary, posting date, source URL, application URL when available, and verification status. Repeated ingestion will use an idempotent upsert based on the source and source job ID. Jobs will also be deduplicated using normalized URLs, company/title/location combinations, and eventually semantic similarity where required. Job freshness will be tracked using fields such as `posted_at`, `first_seen_at`, `last_seen_at`, and `last_verified_at`; jobs that are no longer available will be marked inactive rather than deleted.

The initial filtering stage will use Adzuna's search parameters for role and location, followed by local filtering for factors such as posting date and salary. Jobs without salary information will normally remain eligible rather than being discarded. Each job will then have a concise structured summary containing the role, seniority, and important skills. This summary, rather than the entire job description, will be embedded and stored in pgvector. A similar structured representation of the candidate will be embedded, allowing the system to perform inexpensive semantic ranking before making expensive LLM calls. For example, hundreds of retrieved jobs can first be reduced to the top 20–30 candidates using filters and embeddings, after which the LLM analyzes only the shortlist. Job-level summaries, embeddings, and analysis results will be cached in PostgreSQL so the same job does not repeatedly consume API or LLM calls.

The LLM analysis stage will produce structured results containing a match score, matched skills, missing skills, experience compatibility, location compatibility, and explanations for the score. When the user selects a job, the system will generate a tailored resume by reordering, selecting, and rewording information already present in the original resume. The generation process will be explicitly constrained against adding new employers, degrees, dates, skills, projects, achievements, or other unsupported facts. A verification stage will then check the tailored resume against the original structured resume and reject or flag unsupported information. Finally, the system will display the job details, match analysis, skill gaps, tailored resume, and available application link. Adzuna's redirect/source URL will be stored separately from a verified employer or ATS `apply_url`, so the UI does not incorrectly represent an aggregator redirect as a direct employer application link. The user will review the generated resume and complete the final application manually.

When Greenhouse and Lever are added, the system will maintain a `companies` table containing information such as company name, ATS type, and ATS slug. Initially, the company list can be curated manually, while relevant companies discovered through job sources can later be added to the table. This allows the ATS ingestion layer to fetch jobs directly from known company boards instead of attempting to search the entire ATS platform. The overall implementation will therefore proceed incrementally: resume parsing → Adzuna ingestion → normalization and deduplication → filtering → embeddings and ranking → LLM job analysis → resume tailoring → fabrication verification → ATS integrations. At each stage, the complete pipeline will be tested end to end before adding the next component.
